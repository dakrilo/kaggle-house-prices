# Журнал проекта House Prices

Подробная история работы по шагам: что делали, какие файлы меняли, какие эксперименты ставили и почему приняли каждое решение. Метрика везде RMSE на логарифме цены (меньше = лучше). CV: StratifiedKFold на 5 фолдов по 10 корзинам цены, среднее ± std по фолдам. Все запуски записаны в `outputs/results.csv`, код и выводы каждого шага в `experiments.ipynb`.

## Шаг 0. Каркас из Титаника

**Цель:** не писать код с нуля, а переиспользовать репозиторий Титаника.

**Что сделали:** скопировали репозиторий Титаника без `data/`, `outputs/` и `.git`, сделали `git init`, создали окружение, скачали данные Kaggle в `data/`. В `config.yaml` поменяли цель (`SalePrice`) и id (`Id`).

**Решение:** код `src/` делаем только под регрессию, без переключателя «классификация / регрессия». Так проще читать; репозиторий Титаника остаётся версией для классификации.

## Шаг 1. EDA

**Цель:** понять данные и составить план предобработки.

**Что сделали:** `eda.ipynb`: типы признаков, пропуски, распределение цены, корреляции, выбросы, категориальные и скошенные признаки.

**Что узнали:**
- 79 признаков: 36 числовых, 43 категориальных. `MSSubClass` записан числом, но это код типа дома.
- Пропуски в 19 столбцах train. У большинства NaN значит «объекта нет» (нет гаража, подвала, бассейна). Проверено на гараже: у всех 81 дома без `GarageType` пусты и остальные гаражные столбцы.
- Цена скошена вправо (skew 1.88), после `log1p` почти симметрична (0.12).
- Сильнейшие признаки: `OverallQual` (корреляция 0.82), `GrLivArea` (0.70), `GarageCars`, `TotalBsmtSF`, район.
- Два выброса: дома 524 и 1299, огромные и высшего качества, но дешёвые. Оба проданы недостроенными (`SaleCondition = Partial`).
- Почти константные признаки (`Utilities`, `Street`, `Condition2`, `RoofMatl`, `Heating`, `PoolQC`) и скоррелированные пары (`GarageCars`–`GarageArea` и др.).

## Шаг 2. Код под регрессию

**Цель:** перевести код Титаника с классификации на регрессию.

**Что сделали:**
- `src/data.py`: `load_data` логарифмирует цель (`log1p`, флаг `data.log_target`), `save_submission` возвращает цену обратно (`expm1`).
- `src/validation.py`: `cross_validate` разбивает StratifiedKFold по корзинам цены (`pd.qcut`, `stratify_bins` в конфиге), считает RMSE и усредняет `predict` на test.
- `src/models.py`: словарь регрессоров (`LinearRegression`, `Lasso`, `Ridge`, `ElasticNet`, KNN, дерево, лес, CatBoost, LightGBM, XGBoost).

**Решение:** стратифицировать по корзинам цены, чтобы в каждом фолде были и дешёвые, и дорогие дома.

## Шаг 3. Бейзлайн

**Цель:** точка отсчёта.

**Эксперименты:** медиана цены для всех домов: CV 0.3998. `LinearRegression` на 4 сильнейших признаках (`OverallQual`, `GrLivArea`, `GarageCars`, `TotalBsmtSF`): CV 0.1842 ± 0.0296, Kaggle 0.18030.

## Шаг 4. Предобработка

**Цель:** подготовить все признаки. Мерили одной моделью, Ridge(alpha=10), меняя по одному пункту.

**Что сделали:**
- `config.yaml`: блок `preprocessing` со списками `fill_none`, `fill_zero` и порядковыми шкалами `ordinal.scales` / `ordinal.columns`; `data.drop_ids`.
- `src/data.py`: функции `fill_absent` (NaN «объекта нет» → `"None"` / 0) и `encode_ordinal` (категории качества → числа), вызываются в `load_data`.

**Эксперименты (CV):**
| Шаг | CV |
|---|---|
| Все 79 признаков как есть | 0.1445 |
| NaN «объекта нет» → `"None"` / 0 | 0.1447 |
| Порядковые шкалы (15 столбцов) | 0.1430 |
| `MSSubClass` → категория | 0.1421 |
| `log1p` для 9 скошенных площадей | 0.1332 |
| Без выбросов 524 и 1299 | 0.1116 ± 0.0119 |
| Без 13 лишних признаков | 0.1112 ± 0.0114 |

**Решения:**
- Заполнение `"None"` / 0 почти не изменило CV, но оставили: это правильная обработка смысла пропуска, без неё порядковые шкалы не работают.
- Константные заполнения и порядковые шкалы делаются до пайплайна: они не зависят от данных, утечки нет. Медиана, масштабирование и OneHot остаются в пайплайне и обучаются на train каждого фолда.
- `PoolQC` убрали из порядковых шкал: с ней CV вырос до 0.1584. Бассейн есть у 7 домов, после StandardScaler признак принимает огромные значения, и модель подстраивается под эти дома (в том числе под выброс 1299).
- Удаление выбросов дало самый большой скачок за проект (0.1332 → 0.1116).
- Удалили 13 признаков: почти константные (`Utilities`, `Street`, `Condition2`, `RoofMatl`, `Heating`), дубли из скоррелированных пар (`GarageArea`, `GarageYrBlt`, `TotRmsAbvGrd`) и почти всегда нулевые (`PoolArea`, `3SsnPorch`, `LowQualFinSF`, `MiscVal`, `MiscFeature`). Признаков стало 65.

**Kaggle:** 0.12569. Разрыв с CV около 0.015: из train выбросы удалены, а в test есть похожий дом (Id 2550, `OverallQual` 10, 5095 кв. футов), линейная модель оценивает его примерно в миллион.

## Шаг 5. Одна модель против среднего по фолдам

**Цель:** проверить, что лучше для сабмита: среднее предсказаний 5 моделей фолдов или одна модель на всём train.

**Эксперименты:** Ridge, среднее 5 фолдов: Kaggle 0.12569; одна модель на всём train: 0.12598. Предсказания отличаются в среднем на 0.25%.

**Решение:** разница в пределах шума, оставили среднее по фолдам: оно получается само из `cross_validate` и не требует отдельного обучения.

## Шаг 6. Классические модели

**Цель:** сравнить все типы моделей ручными сетками параметров.

**Эксперименты (лучшее CV каждой модели):**
| Модель | CV |
|---|---|
| Lasso (alpha 0.0003) | 0.1108 |
| ElasticNet | 0.1108 |
| Ridge (alpha 10) | 0.1112 |
| CatBoost (lr 0.05, depth 4) | 0.1127 |
| XGBoost (lr 0.03, depth 3) | 0.1137 |
| LinearRegression | 0.1164 |
| LightGBM | 0.1196 |
| Случайный лес | 0.1323 |
| KNN | 0.1621 |
| Дерево | 0.1836 |

**Что увидели:** у Ridge, Lasso и ElasticNet ошибка по alpha образует «яму»: слабый штраф переобучает, сильный недообучает. У деревьев и бустингов выигрывают неглубокие деревья.

**Решение:** в config лучшей моделью стала Lasso. На Kaggle она дала 0.12797, хуже Ridge (0.12569), но решения принимаем по CV: разница на лидерборде меньше разброса по фолдам.

## Шаг 6а. Optuna

**Цель:** подобрать параметры автоматически вместо ручных сеток.

**Что сделали:**
- `src/tuning.py`: `suggest_params` (берёт у Optuna значения по описанию из конфига: int, float, categorical, логарифмическая шкала) и `tune` (целевая функция возвращает средний RMSE из `cross_validate`, сэмплер TPE с фиксированным seed).
- `config.yaml`: `tuning.space` (пространства поиска), `tuning.fixed` (неподбираемые параметры), `tuned` (лучшие найденные параметры, округлённые).
- `requirements.txt`: `optuna`, `ipywidgets`.

**Эксперименты:** Lasso 0.1106 (alpha 0.00041), XGBoost 0.1115, CatBoost 0.1117, LightGBM 0.1144. Прирост к ручной сетке у бустингов 0.001–0.005 (больше всего у LightGBM), у Lasso почти ноль: один параметр сетка находит и так.

**Kaggle:** XGBoost 0.12464, лучший результат на тот момент, хотя по CV он хуже Lasso. Деревья не продолжают прямую за пределы данных и не завышают дом 2550.

## Шаг 7. Новые признаки

**Цель:** проверить, помогают ли признаки, построенные из существующих.

**Что сделали:** `src/features.py`, функция `add_features`: 11 признаков (общая площадь, всего ванных, площадь веранд, возраст дома и ремонта, флаги гаража, подвала, второго этажа и камина, качество × площадь, квадрат качества). В модель идут только признаки, перечисленные в config.

**Эксперименты (Lasso, база 0.1106):** все 11 сразу 0.1093; по одному: суммы и возрасты почти не меняют CV, `Qual2` (квадрат качества) 0.1096. Лучший набор `Qual2` + `HasGarage` + `HasBsmt`: 0.1092. XGBoost со всеми 11: 0.1115, без изменений.

**Решение:** добавили в config 3 признака. Суммы и разности не помогают линейной модели, потому что это линейные комбинации признаков, которые у неё уже есть. Помогает нелинейный признак: каждая следующая ступень качества добавляет к цене больше. Бустингу признаки не нужны: деревья сами строят такие зависимости.

**Kaggle:** 0.12887, хуже, чем без признаков. Квадрат качества поднял оценку дома 2550 с 1.03 до 1.07 млн.

## Шаг 8. Нейросеть

**Цель:** проверить MLP на задаче регрессии.

**Что сделали:** `src/nn.py`: `MLPRegressorTorch` в обёртке sklearn (работает в Pipeline, CV и ансамблях). `MSELoss`, нормировка цели внутри `fit`, выбор оптимизатора (Adam, AdamW, SGD с momentum), cosine scheduler, прогресс-бар `tqdm` по эпохам с loss (параметр `verbose`). В `tuning.py` добавили тип `categorical`.

**Эксперименты:**
- Лучшие настройки Титаника (3 слоя × 32, dropout 0.5): 0.1360.
- Ручная серия, меняли по одному параметру: без dropout 0.1403 (переобучение), SGD 0.1152 (лучший), 128 нейронов 0.1198, AdamW 0.1203.
- Optuna, 30 попыток: 0.1088, лучшее CV одиночной модели в проекте. 1 слой × 256, SGD, lr 0.0064, 200 эпох, dropout 0.35, weight decay 0.0065, GELU, без BatchNorm.

**Решение:** в config осталась Lasso: качество то же, модель проще. Параметры MLP сохранили в `tuned.mlp` для ансамбля.

**Kaggle:** 0.12544, второй результат после XGBoost.

## Шаг 9. Ансамбли

**Цель:** проверить, помогает ли смешивание моделей. В Титанике не помогло.

**Что сделали:** OOF-предсказания четырёх лучших моделей через `cross_val_predict` на тех же фолдах, корреляции, перебор всех комбинаций для простого среднего, `VotingRegressor` и `StackingRegressor`.

**Эксперименты:**
- Корреляции OOF: Lasso–MLP 0.996, XGBoost–CatBoost 0.995, линейные против бустингов 0.989–0.990.
- Простое среднее: 10 из 11 комбинаций лучше любой одиночной модели. Лучшая Lasso + MLP + XGBoost (OOF RMSE 0.1072), хуже всех XGBoost + CatBoost (0.1121).
- Voting (Lasso + MLP + XGBoost): CV 0.1064 ± 0.0132. Stacking с `LinearRegression` сверху 0.1069, с `Ridge` 0.1066.

**Решение:** финальная модель VotingRegressor. Он лучший по CV и проще Stacking. Stacking не помог: модели почти равны по качеству, равные веса уже близки к оптимальным, а подобранные веса подгоняются под фолды.

**Kaggle:** 0.12364, лучший результат проекта. Оценка дома 2550 снизилась до 980 тыс.: бустинг в смеси сдерживает линейные модели.

## Шаг 10. Финальная модель и итоги

**Цель:** воспроизводить лучшую модель одной командой и подвести итоги.

**Что сделали:**
- `config.yaml`: `model.name: voting`, `model.members: [lasso, mlp, xgb]`, параметры участников берутся из `tuned`.
- `src/models.py`: `build_single` (пайплайн одной модели) и `build_model`, который для `voting` собирает `VotingRegressor`.
- `main.py`: без изменений, кроме фильтра предупреждения OneHotEncoder о редких категориях.
- `reports/summary.csv` и `reports/cv_vs_kaggle.png`: итоговая таблица и график CV против Kaggle.

**Проверки:**
- `run_model(config)` из ноутбука даёт CV 0.1064 ± 0.0132, как в шаге 9.
- `python main.py` даёт тот же CV, а его сабмит совпадает с отправленным на Kaggle: максимальная разница 0.0.

**Итог:** Kaggle хуже CV на 0.013–0.020 у всех моделей (меньше всего у XGBoost, 0.0131, больше всего у Lasso с новыми признаками, 0.0197). Порядок одиночных моделей на CV и Kaggle разный: разница между ними 0.001–0.005, меньше std по фолдам. Ансамбль лучший в обоих рейтингах.

## Что не сработало

- **`PoolQC` в порядковой шкале:** CV 0.1430 → 0.1584. Редкий признак после масштабирования даёт огромные значения.
- **`LotFrontage` медианой по району** вместо общей медианы: CV не изменился, оставили общую медиану в пайплайне.
- **Заполнение «объекта нет»** само по себе не улучшило CV (0.1445 → 0.1447), но понадобилось для порядковых шкал.
- **Одна модель на всём train** вместо среднего по фолдам: на Kaggle то же самое (0.12598 против 0.12569).
- **Суммы, разности и возрасты** как новые признаки: для линейной модели это линейные комбинации, прироста нет.
- **Новые признаки для XGBoost:** CV без изменений.
- **Настройки сети из Титаника:** 0.1360, хуже Lasso на 0.025. Помогли SGD и подбор через Optuna.
- **Stacking:** хуже простого среднего (0.1066–0.1069 против 0.1064).
- **Смесь двух бустингов** (XGBoost + CatBoost): 0.1121, хуже каждой из лучших одиночных моделей. Похожие модели не исправляют ошибки друг друга.
